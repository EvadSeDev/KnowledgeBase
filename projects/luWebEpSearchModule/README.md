# KnowledgeBase Workflow для luWebEpSearchModule

## Назначение

Каталог `KnowledgeBase/projects/luWebEpSearchModule/` предназначен для накопления и сохранения знаний о проекте `luWebEpSearchModule`.

Основные цели:

- не терять результаты исследований;
- не повторять одни и те же расследования;
- сохранять архитектурные решения и особенности проекта;
- предоставлять AI-агентам актуальный контекст для разработки и анализа;
- ускорять расследование инцидентов и исправление дефектов;
- уменьшать зависимость знаний от конкретного разработчика.

KnowledgeBase — дополнительный слой проектной документации для знаний, которые неочевидны из исходного кода.

## Основные принципы

1. Любое завершённое расследование должно быть сохранено.
2. Любое найденное архитектурное ограничение должно быть задокументировано.
3. Любая нетривиальная конфигурация должна быть описана.
4. `AGENTS.md` содержит только итоговые знания и ключевые выводы.
5. Подробные исследования хранятся в отдельных документах.
6. Новый участник команды или AI-агент должен быстро войти в контекст, прочитав документы KnowledgeBase.

## Язык документации

Техническая документация ведётся на английском языке. Это относится к:

- `AGENTS.md`;
- `architecture.md`;
- `validation.md`;
- `deployment.md`;
- `swagger.md`;
- `troubleshooting.md`;

README допускается вести на русском языке для удобства участников команды. Английский используется в технических документах ради единой терминологии с исходным кодом и совместимости с AI-инструментами.

## Роли основных файлов

### `AGENTS.md`

Главная точка входа для AI-ассистентов. Содержит краткий обзор архитектуры, ключевые сервисы, validation flow, deployment invariants, known limitations, lessons learned, команды и ссылки на расследования.

Если информация занимает больше нескольких абзацев или содержит подробный экспериментальный материал, её следует вынести в отдельный документ.

### `architecture.md`

Описывает основные компоненты, границы сервисов, потоки запросов, бизнес-процессы и интеграции с внешними зависимостями.

### `validation.md`

Содержит знания о Bean Validation, Hibernate Validator, `BeanValidationUtils`, `@ValidQueryType`, `@ValidSearchCriteria`, `QueryTypeValidator` и `SearchCriteriaValidator`.

### `deployment.md`

Описывает запуск и поставку через Tomcat, Docker, Kubernetes и Helm, внешнюю конфигурацию и переменные окружения.

### `swagger.md`

Документирует legacy Swagger 1.x, ограничения генерации Example Value и ручное описание кастомных validation rules.

### `troubleshooting.md`

Содержит краткий индекс типовых диагностических направлений и ссылки на подробные investigations. Логи, stacktraces и экспериментальные данные должны храниться в investigation-файлах, а не в `AGENTS.md`.

### `workflow.md`

Является основным операционным руководством по работе с KnowledgeBase. В нём описывается:

- как AI-агенты должны использовать `AGENTS.md` перед началом задачи;
- когда создавать новые investigation-файлы;
- когда обновлять существующие расследования вместо создания новых;
- как обновлять KnowledgeBase после завершения анализа;
- какие prompt-шаблоны использовать для типовых задач;
- как поддерживать актуальность документации.

### `investigations/`

Содержит завершённые и продолжающиеся расследования. Каждый файл должен фиксировать проблему, шаги воспроизведения, диагностику, собранные факты, выводы и follow-up actions.

## Использование KnowledgeBase

- `README.md` объясняет структуру KnowledgeBase, назначение документов и общие правила её ведения.
- `AGENTS.md` содержит концентрированные знания о проекте и является основной точкой входа для AI-агентов.
- `workflow.md` содержит практические инструкции по использованию базы знаний и поддержанию документации.
- `investigations/` хранит подробную историю расследований, доказательства, логи, диагностику и выводы.
- Для новой задачи следует начинать с `AGENTS.md`, затем читать тематические документы.
- Для продолжения расследования необходимо прочитать `AGENTS.md` и соответствующий investigation-файл.
- Перед созданием нового investigation-файла нужно проверить, нет ли уже документа по этой теме.
- KnowledgeBase следует рассматривать как долговременную память проекта: новые подтверждённые знания нужно сохранять, а не оставлять только в чате, issue или локальном контексте агента.

Рекомендуемый порядок работы:

```text
README.md
    ↓
AGENTS.md
    ↓
workflow.md
    ↓
investigations/*.md
```

Назначение уровней:

- `README.md` объясняет структуру KnowledgeBase, назначение документов и общие правила её ведения.
- `AGENTS.md` содержит концентрированные знания о проекте и является основной точкой входа для AI-агентов.
- `workflow.md` содержит практические инструкции по использованию базы знаний и поддержанию документации.
- `investigations/*.md` хранит подробную историю расследований, доказательства, логи, диагностику и выводы.

## Источники реализации

D:/project/liga/ips_united/luwebepsearchmodule
```

Операционные инструкции проекта находятся в repository `README.md`. Characterization-тесты и ограничения logical search описаны в `README_LogicSearchRegressionTests.md`.

## Высокоценные расследования

Перед началом нового анализа необходимо проверить документы по следующим темам:

- `@ValidQueryType` и `QueryTypeValidator`;
- цепочка `BeanValidationUtils`;
- `@ValidSearchCriteria`;
- ограничения Swagger 1.x;
- требования `ExternalConfigurationListener`;
- правила расположения `WebEPSearch.properties`;
- DEV deployment structure;
- загрузка внешней конфигурации Tomcat;
- WSL/local build issues.
